# Content-free save measurements

The shared revisioned controller measures save duration, operation category, failure class, retry count and payload byte count. It never submits the payload. Metrics have a fresh random correlation ID unrelated to the account, entity, URL or operation receipt. Strict schemas on both client and server reject unknown fields, free-form errors, note/board contents, answers, tokens and personal identifiers. Account transitions clear the bounded200-entry memory buffer and invalidate late measurements.

Reporting is off by default. `inspectOperationMetrics()` exposes measurements for local diagnostics. With `VITE_TELEMETRY_ENABLED=true` and server `TELEMETRY_ENABLED=true`, authenticated batches go only to `/api/telemetry`; the server validates the JWT and logs only the schema-approved values. The endpoint has a16KiB body limit,20-metric batch limit and a per-instance rate budget; infrastructure-level abuse/rate controls and log retention still require deployment configuration. Delivery failure cannot interrupt saving and does not expose provider exceptions; its buffer remains bounded. No third-party analytics SDK or content collection was added.

Set `VITE_RELEASE_SHA` to the40-character candidate SHA during build. Configure restricted operational log access and short retention before enabling production collection. Review aggregate save failure rate, conflict rate, retry count, payload size and latency by release; do not add user IDs to make correlation easier. Tests prove rejection of content/token fields, bounded buffers, account reset races, server authorization and actual request-size limits.
