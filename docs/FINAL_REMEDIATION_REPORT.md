## 7. DATABASE AND DATA SAFETY

Historical migrations are immutable. The known 0016 pair is combined only in a fresh temporary bundle with source hashes; unknown duplicate versions fail. Production history is never repaired by blindly renaming files or marking versions applied. Additive migrations 0026–0041 implement authorization/creator separation, revision checks, trusted seeding, billing leases, canonical review, trash, canonical board history, private assets, archives, account lifecycle, evidence fields, bounded search and deletion/session boundaries.

Clean and three supported upgrade scenarios all pass the final real native database matrix. Upgrade fixtures retain meaningful existing rows and content. Roles tested are anon, learner A, learner B, paid creator, operator and service role. The production-observed fixture reproduces selected read-only metadata; its success does not eliminate uncertainty about the hosted database's full schema or data.

Critical preservation rules:

- Content updates use expected revisions and idempotent operation receipts; direct browser content writes cannot bypass them.
- Current whiteboard scene and version commit atomically. Unequal legacy scene copies abort migration; 50 latest automatic/draft versions are retained alongside all manual/checkpoint versions. No production history was pruned.
- Archive restore is insert-only and atomic, checks owners/parents/assets, retains source/history and rolls back malformed input; owner assets are locked before promotion.
- Deletion checks active billing under a lease and fences new writes. It refuses published/shared dependencies and legacy foreign-owned children rather than allowing profile cascades to erase another learner's work. New attachments serialize with deletion, proven with competing transactions. Operator reconciliation is required for those shared accounts.
- Real local global logout invalidates old JWT data access immediately through server session checks. Pending deletion can still reach session-only Account retry; network failures do not erase drafts or sign out another account.
- No production data, hosted schema, paid branch or live provider account was mutated. Local platform manifests and credentials remain private.

Database rollback is forward-compatible application rollback with additive schema retained; see section10. A pre-CAS/direct-write client or one selecting removed scene aliases is not a safe fallback after 0027/0032.
